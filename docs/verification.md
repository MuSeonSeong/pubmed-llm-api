# 구현 및 검증 결과

2026-10-09, Apple M5 / RAM 16 GB. 상세 실행 결과는 README의 실제 검증 표를 참조합니다.

## 완료 범위

- 새 독립 저장소의 main 초기화 및 구현 커밋
- 로컬 .venv, uv 잠금 파일, Transformers 기반 CPU/MPS/CUDA 장치 선택
- Qwen3-0.6B 및 Qwen3.5-2B 원본 모델 파일 준비
- FastAPI/Uvicorn API, 실제 PubMed MCP 검색 및 초록 조회
- Docker 이미지 및 Compose 실행 확인
- 단위·HTTP 계약 테스트 62개 통과

## 최종 검토 수정

새 리뷰어가 전체 구현을 검토했습니다. 샤드 인덱스가 없는 모델을 준비 완료로 판단하던 문제를 수정했습니다. 실제 모델 파일에 의존하던 MPS 로딩 단위 테스트도 독립 fixture로 바꿨습니다. 두 문제 모두 수정 전 실패와 수정 후 통과를 확인했습니다. 남긴 미수정 검토 항목은 없습니다.

최종 Docker 이미지를 다시 빌드해 HTTP 채팅을 확인했습니다. Qwen3-0.6B CPU에서 2+2=4 응답을 받았으며 HTTP 200, 첫 로드 포함 약 9.4초였습니다. 테스트 컨테이너와 네트워크는 정리했습니다.

## 구현 판단과 영향

1. 승인받은 새 프로젝트의 main에서 직접 작업했습니다. 별도 저장소가 원래 프로젝트와 격리됩니다. 나중에 별도 작업 브랜치가 필요하면 구현 커밋을 옮겨야 합니다.
2. MPS는 CPU에서 로딩한 뒤 MPS로 옮깁니다. 설치된 Torch/Transformers에서 직접 MPS 로딩은 충돌했고 CPU 경유 방식은 실제 실행에 성공했습니다. 일시적인 CPU 메모리와 로딩 시간이 추가됩니다.
3. Qwen3 JSON 및 Qwen3.5 공식 XML 도구 호출을 모두 지원합니다. 공식 템플릿과 실제 생성 결과에 맞춘 결정입니다. 이후 템플릿이 바뀌어 지원하지 않는 형식이 나오면 HTTP 502로 실패합니다.
4. Windows 및 CUDA 실장비 실행은 검증하지 못했습니다. 이식 가능한 소스와 설치 명령은 제공했으며 해당 하드웨어에서 추가 수정이 필요할 수 있습니다.

## ChatGPT형 웹 UI 확장 — 2026-10-09

`feat/chatgpt-web-ui` 브랜치에서 진행했습니다. 기능별 사용법은 README의 "브라우저에서 채팅하기"와 API 절을 참조합니다.

### 추가한 기능

- **서버**
  - SSE 스트리밍. 연결이 끊기면 생성을 중단합니다.
  - 긴 대화 자동 정리(`truncate_history`)
  - 추론 모드(`thinking`, `reasoning_content`)
  - 답변 이어서 생성(`continue_final`)
  - PubMed 출처 메타데이터(`sources`)와 OpenAI 형식 `id`·`usage`
  - Qwen3.5 이미지 입력
  - PDF 텍스트 추출 엔드포인트
  - 대기(`queued`) 상태 보고
- **웹 UI**
  - 스트리밍 표시, 중지
  - 답변 다시 생성(버전 넘기기), 질문 수정, 이어서 생성
  - 추론 패널, 출처 카드
  - 이미지·PDF·텍스트 첨부, 붙여넣기·끌어다 놓기
  - 대화 검색·고정·이름 변경, 마크다운·JSON 내보내기
  - 맞춤 지시문·창의성·답변 길이 설정, 다크 모드
  - 소리 내어 읽기, 코드 구문 강조와 복사, 표·목록 서식
  - 여러 탭 동시 사용(Web Locks 기반 잠금과 병합)

### 검증 방식

- 단위·계약 테스트는 pytest(서버)와 `node --test`(브라우저 상태 로직)로 실행합니다.
- 기능마다 실제 서버(MPS)와 Chromium(Playwright)으로 실제 모델 응답을 확인했습니다.
- Docker CPU 이미지를 다시 빌드해 웹 UI, 스트리밍, 이미지 검증 경로를 확인했습니다.
- 독립 리뷰어가 단계마다 변경을 검토했습니다. 지적된 버그는 모두 회귀 테스트와 함께 수정했습니다.
  - 탭 간 데이터 손실
  - 이름 변경 포커스 문제
  - 수정 중 입력 손실
  - 출처가 붙은 답변의 이어 쓰기
  - 도구 결과의 null 목록 처리

### 남은 제한

- 이미지는 Qwen3.5-2B만 이해합니다. 이미지 하나는 약 256토큰을 차지합니다.
- 기본 문맥을 4096에서 8192토큰으로 올렸습니다. 종합 리뷰에서 첨부, PubMed 초록 조회, 추론을 함께 쓰면 4096으로는 413이 흔하다고 측정됐기 때문입니다. 이제 프롬프트가 남긴 만큼 답변 길이를 줄여 답합니다.
- 스캔한 PDF(글자 없는 이미지)는 읽지 못합니다. 첨부 텍스트는 12,000자로 제한됩니다.
- 이 단계에서는 대화 기록을 브라우저 localStorage에만 저장했습니다. 이후 서버 저장으로 바꿨습니다(아래 "서버 저장과 계정").
- Windows/Linux 네이티브와 CUDA 환경에서는 웹 UI 기능을 실제로 검증하지 못했습니다.

## 서버 저장과 계정 — 2026-10-09

대화를 이 프로젝트의 서버에 계정별로 저장하고, 이 PC를 친구들이 인터넷으로 쓰는 서버로 만들었습니다. 사용법은 README의 "대화 저장 API"와 "서버 PC로 배포하기", 그리고 [deploy.md](deploy.md)를 참조합니다. 저장소로 Redis 대신 SQLite를 고른 이유도 deploy.md에 있습니다.

### 추가한 기능

- **서버**
  - `data/chat.db`(SQLite, WAL)에 계정·세션·대화·설정, `data/files/`에 첨부 이미지. `data/`는 Git에서 제외
  - 대화마다 rev, 변경마다 전역 seq, 삭제 기록(tombstone)으로 여러 기기 동기화
  - scrypt 비밀번호, 로그인 시도 제한, HttpOnly 세션 쿠키, CSP 등 보안 헤더, 계정별 저장 용량 제한
  - 답변 중인 대화(`live`) 표시, 계정당 동시 답변 2개, 15초마다 `: ping`
- **웹 UI**
  - 로그인 화면. 브라우저는 계정별 사본(캐시)만 두고 서버와 동기화
  - 첨부 이미지 업로드, 서버 저장 전 기록 한 번 가져오기, 다른 기기에서 답변 중인 대화는 읽기 전용
- **배포**
  - `scripts/users.py`(계정 관리), `scripts/serve.py`(계정 모드, 127.0.0.1, 잠자기 방지)
  - macOS LaunchAgent 설치·해제 스크립트, Cloudflare Tunnel 설정 예시

### 검증 방식

- pytest 292개, `node --test` 90개(`tests/chat.test.mjs`, `tests/sync.test.mjs`)가 통과했습니다.
- 빈 `DATA_DIR`로 실제 `scripts/serve.py`를 계정 모드로 실행해 확인했습니다(포트 8771, Qwen3-0.6B MPS).
  - CLI 15개 항목: 계정이 없거나 `AUTH_ENABLED=false`면 시작하지 않음, 한글 이름 계정 만들기, 예약 이름·짧은 비밀번호 거절
  - curl 78개 항목: 로그인 전 `/`→`/login`, `/docs` 404, API 401, 쿠키 속성(https 프록시 뒤에서 `Secure`), 대화의 seq·409·410·삭제 기록, 설정, 업로드 형식 판별, 다른 계정의 파일 404, 스트리밍 중 `live`와 세 번째 요청 429 `busy`, Qwen3-0.6B에 이미지 422 `vision_unsupported`(2B는 불러오지 않음), 로그인 시도 제한, 로그아웃
  - 웹 UI 모듈(ChatStore, RemoteSync)을 Node에서 실제 서버에 연결해 23개 항목: 두 기기 동기화, 다른 기기의 답변을 읽기 전용으로 지켜보다 최종 답 받기, 409·410 처리, 업로드, 예전 기록 가져오기
  - 헤드리스 Chrome 20개 항목: 로그인(Enter)·로그아웃, 동기화 상태 표시, 이미지 첨부 미리보기, 빈 계정에 예전 기록 제안, CSP 위반과 콘솔 오류 없음
  - 실행 중에는 `caffeinate`가 서버 프로세스를 대신해 잠자기를 막고, 종료하면 풀림

### 통합하며 고친 점

- 스크립트가 실행되기 전에 로그인 폼에서 Enter를 누르면, 브라우저가 폼을 GET으로 보내 비밀번호가 주소창·방문 기록·접속 로그(`data/logs/access.log`)에 남을 수 있었습니다. 폼을 POST로 바꾸고, 로그인 버튼은 스크립트가 켤 때까지 비활성으로 둡니다.
- 문서에 로컬 모드 대화를 계정으로 옮기는 `users.py adopt-local`을 추가했습니다. 정적 파일의 `no-cache`에 맞게 Cloudflare 캐시 안내를 고치고, 복원할 때 `data/` 권한(700)을 지키게 했습니다.

### 남은 제한

- 로그인 시도 제한, `live` 표시, 동시 답변 수는 메모리에 있어 서버 프로세스(워커) 1개를 전제로 하며 재시작하면 초기화됩니다. `scripts/serve.py`는 워커 1개로 실행합니다.
- Cloudflare Tunnel·Tailscale Funnel을 통한 실제 인터넷 접속과 LaunchAgent 실제 등록은 실행하지 않았습니다. 설정 파일 검증과 `--dry-run`, 임시 명령으로 바꾼 설치 시험만 했습니다.
- Docker 이미지는 다시 빌드하지 않았습니다.
